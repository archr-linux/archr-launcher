# API de temas 3.1.0: o tema alcança todas as telas

Pedido do Douglas (2026-11-17), ao aprovar as maquetes do tema Ellegance:
"Se o tema não consegue chegar em todas as telas, avance a API de temas para
cobrir o que for necessário. Isso também sairá junto da 3.1.0."

Hoje o `theme.toml` posiciona só as telas de sistemas e de jogos
(`[view.<id>.systems|games]`) e alguns blocos soltos (`details_*`,
`achievements_*`, `saves_*`, `shots_grid`, `switcher_*`, `resume_*`,
`start_area`). Start, menu do jogo, busca, teclado, avisos, diálogos,
Configurações e o OSD têm a geometria fixa no código. O tema Ellegance
(maquetes aprovadas no quadro, página "Ellegance (3.1)") precisa de uma
navegação nova e de layout próprio em todas elas.

Regras que continuam valendo (docs/temas.md, memória launcher-temas-layout):

- Tudo é dado do `theme.toml`, desenhado por um caminho parametrizado; nada de
  layout fixo novo em Rust.
- Toda chave é opcional e herda campo a campo do tema padrão; chave
  desconhecida ou tipo errado gera aviso no log e nunca derruba o launcher.
- Frações da tela para retângulos (`x`/`w` da largura, `y`/`h` da altura),
  tamanhos em frações dos 480 px de referência, `[aspect.*]` por cima.
- Um tema que não usa nada desta spec desenha exatamente como hoje (os golden
  de `tests/golden/640x480` não mudam).

## 1. Base

### 1.1 Setas e ombros separados

`Button` ganha `Left` e `Right`. O pad deixa de traduzir ← → para `L`/`R`.
Para manter o comportamento atual, as telas existentes tratam
`Left|L` e `Right|R` juntos; só a navegação de prateleiras (2) e quem pedir
distingue. O remapeamento dos controles do launcher passa a listar ← e →.

### 1.2 Primitivas de estilo (`[style]`, já existe; chaves novas)

| chave | valores | efeito |
|---|---|---|
| `font_bold` | arquivo da fonte | terceira face de UI (peso 700); `Face::Bold`. Sem ela, negrito sintético como hoje |
| `shadow_color` | cor | cor da sombra suave (hoje preta fixa) |
| `shadow_blur` | fração | raio da sombra suave |
| `shadow_offset` | fração | deslocamento vertical da sombra |
| `glass` | `{ fill, border, highlight, blur }` | material de vidro: preenchimento translúcido, borda de 1 px, brilho de 1 px no topo e desfoque do fundo por trás (`blur` em frações; 0 desliga) |
| `focus` | `"pill"` (atual) \| `"lift"` | `lift`: o item em foco cresce (`focus_scale`), ganha sombra e um contorno (`focus_ring`, cor e largura) |
| `focus_scale` | 1.0–1.15 | crescimento do item em foco no modo `lift` |
| `focus_ring` | `{ color, width }` | contorno do foco |
| `motion` | `"tween"` (atual) \| `"spring"` | mola criticamente amortecida (resposta 0,3–0,4 s) em vez de curva fixa; com Animações desligadas, sem movimento |

Desfoque: nunca por quadro. O fundo desfocado (arte do sistema, captura do
jogo) é gerado uma vez por imagem, por redução e ampliação linear em
textura (render-to-texture já existe em `effects.rs`), e guardado em cache
como as capas. O vidro "desfoca" desenhando o recorte correspondente dessa
textura pronta. Custo a medir no R36S antes de fechar (meta: troca de
sistema sem quadro perdido).

Gradientes: `gradient = { from, to, angle }` onde hoje se aceita uma cor
sólida de fundo de painel ou de fundo de tela (`angle` 0 = horizontal,
90 = vertical).

Opacidade por elemento: todo elemento de layout aceita `opacity` (0–1).

### 1.3 Sons: sem mudança.

## 2. Navegação de prateleiras (`[view.<id>.home]`)

Uma visualização pode declarar `home`. Com ela, a tela inicial deixa de ser
a lista/carrossel de sistemas e passa a ser a Início com abas:

```toml
[view.ellegance]
name = { en = "Shelves", pt_BR = "Prateleiras" }
home = true

[view.ellegance.home.tabs]          # cápsula de abas no topo
items = ["home", "library", "favorites"]
rect = { x = 0.29, y = 0.03, w = 0.42, h = 0.07 }
style = "glass"

[view.ellegance.home.hero]          # destaque do item em foco
rect = { x = 0.05, y = 0.15, w = 0.5, h = 0.33 }
art = { x = 0.55, y = 0.14, w = 0.41, h = 0.32, fit = "contain" }
backdrop = { blur = 0.1, opacity = 0.6 }   # arte do item, desfocada, atrás
actions = ["play", "favorite", "more"]

[view.ellegance.home.shelves]
order = ["continue", "systems", "apps"]
y = 0.51                            # topo da primeira prateleira
gap = 0.03
title = 0.027                       # tamanho do título da prateleira
[view.ellegance.home.shelves.continue]
item = { w = 0.234, h = 0.175, radius = 0.033 }
progress = true                     # barra de progresso (onde houver dado)
[view.ellegance.home.shelves.systems]
item = { w = 0.144, h = 0.121, radius = 0.029 }
```

- Prateleiras disponíveis: `continue` (recentes, `Store.recent`, com a captura
  do `switcher()`), `systems`, `favorites`, `apps` (apps de módulos),
  `collections`. Prateleira vazia some.
- Abas: `home` (Início), `library` (Biblioteca: grade de todos os sistemas;
  A abre o sistema numa grade de jogos com faixa de sistemas trocada por
  L1/R1), `favorites` (favoritos em prateleiras por sistema).
- Entrada: ↑↓ troca de prateleira (o destaque segue o item em foco), ← → anda
  na prateleira, L1/R1 troca de aba, A abre/joga, Y menu do jogo, B volta
  (na Início, B não faz nada; Start abre o Menu Start).
- Estado: `Screen::Home { tab, shelf, item }`; `history`/`back` voltam para
  ela quando a visualização tem `home`.
- `[view.<id>.library]` e `[view.<id>.games]`: a grade de jogos ganha
  `list.mark = "grid"` com `columns`, `item` e rótulo embaixo; `strip`
  (faixa de sistemas) é um elemento novo com `rect`.

## 3. Uma tabela por tela

Cada tela ganha uma tabela de topo (fora de `[view]`, vale para todas as
visualizações; uma visualização pode sobrescrever dentro dela). Os blocos
atuais (`details_*`, `achievements_*`, `saves_*`, `shots_grid`,
`switcher_*`, `resume_*`, `start_area`) continuam aceitos e viram atalhos
dessas tabelas.

| tabela | tela | o que o tema decide |
|---|---|---|
| `[start]` | Menu Start | `tiles` (rect, colunas, altura, `style`), `shortcuts` (rect, tamanho, forma `circle`/`square`), `clock` (rect, tamanho; mostra hora grande), `status` (rede e bateria), `caption` (nome do item em foco) |
| `[menu]` | menu do jogo (Y) e menu rápido | `style = "list"` (atual) \| `"context"` (estilo iOS: ancorado ao item em foco, `quick` = ações rápidas em botões no topo, seções com título, ação destrutiva em vermelho); `rect` ou `anchor`, `width`, `row`, `radius` |
| `[details]` | detalhes do jogo | os `details_*` atuais + `style = "hero"` (destaque de tela cheia com a arte desfocada, título grande, botões e prateleira "Mais do sistema") |
| `[achievements]` | conquistas | `progress` (`bar` \| `ring`), `list` (rect, `row`, `gap`), `badge` (tamanho, raio) |
| `[saves]` | saves | `preview` (rect), `list` (rect, `row`, `thumb`) |
| `[shots]` | capturas | `grid` (rect, `columns`, `gap`, `radius`), `sections` (agrupar por data) |
| `[switcher]` | alternador | `cards` (`depth`: cartões em profundidade), `card`, `side`, `info` |
| `[resume]` | retomar ao ligar | `title`, `progress`, `backdrop` |
| `[search]` | busca | `field` (rect, raio), `results` (rect, `row`, `thumb`), `keyboard` (`dock = "bottom"`) |
| `[keyboard]` | teclado na tela | `rect`, `key` (w, h, gap, raio), `sheet = true` (folha com Cancelar/confirmar no topo) |
| `[toast]` | avisos | `position` (`top`/`top-right`/...), `width`, `icon` (forma) |
| `[dialog]` | confirmações e alertas | `width`, `icon` (círculo com ícone), `buttons` (`row` \| `column`), `radius` |
| `[hints]` | dicas de botões no rodapé | `style = "bar"` (atual) \| `"capsule"` (cápsula de vidro), `position` |
| `[status]` | pílula de relógio e bateria | rect, o que mostrar |

## 4. Configurações

Revoga a exceção de 2026-10-28 (Configurações só com cores, fontes e
ícones).

```toml
[settings]
layout = "sidebar"                  # "list" (atual) | "sidebar"
sidebar = { x = 0.022, w = 0.334, style = "glass", title = 0.046 }
row = 0.075
icon = "tile"                       # "plain" (atual) | "tile": ícone branco em quadrado colorido
groups = "inset"                    # "flat" (atual) | "inset": linhas em grupos arredondados
[settings.icon_colors]              # por página; padrão do tema se ausente
network = "#0A84FF"
sound = "#FF375F"
```

`sidebar`: a raiz vira barra lateral fixa à esquerda e a página escolhida
abre à direita (dois níveis numa tela). `list`: comportamento atual. O
picker segue o mesmo `groups`.

## 5. OSD (`archr-osd`)

O OSD passa a ler do tema ativo um subconjunto: `[osd]` com `style`
(`pill` atual, `capsule` vertical), `fill`, `track`, `radius`, `position`,
e as cores e fontes do tema. O launcher grava o tema ativo resolvido em
`/run/archr-launcher/osd-theme.toml` ao aplicar a aparência; o OSD relê no
`SIGHUP` ou a cada exibição se o arquivo mudou.

## 6. Ordem de implementação

1. Base (1.1 e 1.2) com testes; golden atuais intactos.
2. Prateleiras (2): estado, entrada, layout, desenho; capturas no PC.
3. Tabelas por tela (3), uma de cada vez.
4. Configurações (4).
5. OSD (5).
6. Tema Ellegance em `themes/ellegance/`, com golden próprios em 640x480,
   720x720 e 480x320.
7. Documentação: docs/temas.md, archr-website content/docs/themes.mdx e
   themes.pt-BR.mdx, skill archr-launcher-dev (references/themes.md,
   checklist, precheck.py com as chaves novas).

Cada etapa: `cargo test -p archr-ui`, `cargo clippy -D warnings`, capturas
do tema padrão (sem mudança) e do Ellegance; no R36S, medir o desfoque e o
tempo de troca de tela antes de seguir.
